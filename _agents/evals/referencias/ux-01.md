## Components Used

- `mol-form-field` (molécula) para el correo y para cada contraseña.
- `atom-btn atom-btn--primary` (átomo) para enviar.
- `atom-link` (átomo) para volver al acceso.
- `mol-alert` (molécula) para la confirmación y el enlace caducado.

## Interaction Flow

1. «¿Olvidaste la contraseña?» en el acceso → página con un solo campo: correo.
2. Enviar → siempre el mismo mensaje: «Si hay una cuenta con ese correo, te hemos enviado un enlace». No revela si la cuenta existe.
3. El enlace abre «Nueva contraseña» (dos campos, requisitos visibles desde el principio).
4. Éxito → sesión iniciada y aviso de que las otras sesiones se han cerrado.
5. Enlace caducado o usado → página propia con el botón para pedir otro, sin volver a escribir el correo si lo conocemos.

## States to Handle

Campo vacío · correo mal formado · enviando · enviado · contraseña que no cumple · contraseñas distintas · enlace caducado · enlace ya usado · error de red.

## Accessibility Notes

- El foco entra en el primer campo; tras enviar, pasa al mensaje de confirmación.
- La confirmación y los errores se anuncian con `aria-live="polite"`; los errores de campo se enlazan con `aria-describedby`.
- Todo se completa con teclado; el ojo de «mostrar contraseña» es un botón con nombre accesible.

## Why

- Mismo mensaje exista o no la cuenta — evita la enumeración de cuentas — si el producto ya revelara las cuentas en el registro, el mensaje podría ser específico sin perder nada.
- `mol-alert` para el enlace caducado y no una página de error genérica — el usuario tiene una acción clara (pedir otro) — si los enlaces no caducaran, el estado desaparecería.
